## Description
Add the single Ktor route group `POST /chat` on the `first` branch: strict request/response per CONTRACT-API-001, no streaming (D-7), masked error bodies. Parse → validate → delegate to `ChatService` → respond; the route holds no business logic (design §2). T11 lands before the service, so this task also declares the seam the route consumes — the `ChatService` interface plus its result/error types (`ChatTurn`, `ChatFailure`) — and binds a placeholder in DI; T12 replaces the placeholder with the real implementation.

## Acceptance Criteria
- [ ] `POST /chat` accepts `{prompt, fueling_id?, provider?}` as `application/json` with kotlinx-serialization DTOs matching CONTRACT-API-001 field-for-field; ContentNegotiation (kotlinx-json) is installed and malformed JSON yields `400 {"error": "<masked message>"}`.
- [ ] Validation per CONTRACT-API-001: blank/whitespace-only `prompt` → 400; `provider` other than `"local"`/`"remote"` (absent → `local`, D-10) → 400; error bodies are masked (never SQL, credentials or raw provider errors).
- [ ] The 200 body is exactly `{summary, provider, elapsed_ms}` (CONTRACT-API-001): `summary` from the service, `provider` = the provider that served the turn, `elapsed_ms` = integer ≥ 0 measured as server wall-clock route entry → response ready.
- [ ] `ChatFailure(status, maskedMessage)` from the service maps to that HTTP status with `{"error": "<masked message>"}`: 500 for the four-DB failure class, 502 for the provider/tool-loop failure class; unmapped service exceptions never leak internals (generic masked 500).
- [ ] The `ChatService` seam declared here carries no business logic: one suspend entry point per turn returning `ChatTurn(summary, provider)` and throwing `ChatFailure`; the DI binding is a placeholder (`error("…")`) that T12 replaces.
- [ ] No streaming primitives anywhere in the route: one request → one response (D-7); `grep -rE "text/event-stream|chunked|webSocket|EventSource" src/main/kotlin/com/fuelingchat/routes` returns nothing.
- [ ] `AppModule.boot()` installs the route; route tests use `testApplication` with a fake `ChatService` seam asserting: 200 shape, the three 400 cases, masked 500, masked 502, and `elapsed_ms ≥ 0` (concurrent requests not required).
- [ ] `./gradlew build ktlintCheck detekt` completes with 0 errors.
