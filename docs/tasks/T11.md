# T11 - Ktor Chat Route

**Status:** `todo`
**Owner:** `backend-coder`
**Dependencies:** `[]`
**Contracts:** `[CONTRACT-API-001]`

## Description
Add the single Ktor route group `POST /chat` on the `usual` branch: strict request/response per CONTRACT-API-001, no streaming (D-7), masked error bodies. Parse → validate → delegate to `ChatService` → respond; the route holds no business logic (design §2). T11 lands before the service, so this task also declares the seam the route consumes — the `ChatService` interface plus its result/error types (`ChatTurn`, `ChatFailure`) — and binds a placeholder in DI; T12 replaces the placeholder with the real implementation.

## Acceptance Criteria
- [ ] `POST /chat` accepts `{prompt, fueling_id?, provider?}` as `application/json` with kotlinx-serialization DTOs matching CONTRACT-API-001 field-for-field; ContentNegotiation (kotlinx-json) is installed and malformed JSON yields `400 {"error": "<masked message>"}`.
- [ ] Validation per CONTRACT-API-001: blank/whitespace-only `prompt` → 400; `provider` other than `"local"`/`"remote"` (absent → `local`, D-10) → 400; error bodies are masked (never SQL, credentials or raw provider errors).
- [ ] The 200 body is exactly `{summary, provider, elapsed_ms}` (CONTRACT-API-001): `summary` from the service, `provider` = the provider that served the turn, `elapsed_ms` = integer ≥ 0 measured as server wall-clock route entry → response ready.
- [ ] `ChatFailure(status, maskedMessage)` from the service maps to that HTTP status with `{"error": "<masked message>"}`: 500 for the four-DB failure class, 502 for the provider/tool-loop failure class; unmapped service exceptions never leak internals (generic masked 500).
- [ ] The `ChatService` seam declared here carries no business logic: one suspend entry point per turn returning `ChatTurn(summary, provider)` and throwing `ChatFailure`; the DI binding is a placeholder (`error("…")`) that T12 replaces.
- [ ] No streaming primitives anywhere in the route: one request → one response (D-7); `grep -rE "text/event-stream|chunked|webSocket|EventSource" src/main/kotlin/com/fuelingchat/routes` returns nothing.
- [ ] `AppModule.boot()` installs the route; route tests use `testApplication` with a fake `ChatService` seam asserting: 200 shape, the three 400 cases, masked 500, masked 502, and `elapsed_ms ≥ 0` (concurrent requests not required).
- [ ] `./gradlew build ktlintCheck detekt` completes with 0 errors.

### Cross-block interfaces

Block 1 exports (routes DTOs):

```kotlin
@Serializable
data class ChatRequest(
    val prompt: String,
    @SerialName("fueling_id") val fuelingId: String? = null,
    val provider: String? = null,
)

val ALLOWED_PROVIDERS: Set<String> = setOf("local", "remote")

fun ChatRequest.validationError(): String?   // masked 400 message, or null when valid
fun ChatRequest.effectiveProvider(): String  // provider ?: "local" (D-10)

@Serializable
data class ChatResponse(
    val summary: String,
    val provider: String,
    @SerialName("elapsed_ms") val elapsedMs: Long,
)

@Serializable
data class ChatErrorResponse(val error: String)
```

Block 2 exports (service seam):

```kotlin
data class ChatServiceRequest(
    val prompt: String,
    val fuelingId: String?,
    val provider: String,     // always the effective provider ("local" default)
)

interface ChatService {
    suspend fun run(request: ChatServiceRequest): ChatTurn
}

data class ChatTurn(
    val summary: String,
    val provider: String,
)

enum class ChatFailureStatus { DATABASE, PROVIDER }

data class ChatFailure(
    val status: ChatFailureStatus,
    val maskedMessage: String,
) : Exception(maskedMessage)
```

Block 3 exports (route):

```kotlin
fun Application.chatRoutes(chatServiceProvider: () -> ChatService)
```

`chatRoutes` installs ContentNegotiation (kotlinx-json) exactly once — no other module may install it again. The provider is lazy so the T11 placeholder binding never fails at boot; it resolves the service only when POST /chat arrives. Consumes the Block 1 DTOs (`ChatRequest`, `ChatResponse`, `ChatErrorResponse`, `validationError()`, `effectiveProvider()`) and the Block 2 seam types (`ChatService`, `ChatServiceRequest`, `ChatTurn`, `ChatFailure`). Failure mapping: `ChatFailureStatus.DATABASE` → 500, `PROVIDER` → 502, unmapped exceptions → generic masked 500.

Block 4 consumes `chatRoutes`, the Block 1 DTOs, the Block 2 seam types, and `io.ktor:ktor-server-test-host-jvm` (integrator-owned dependency). The fake seam is the private `FakeChatService` declared inside the test file — signature pinned by the scaffold.

Integrator wiring (scaffolded by the architect; integrator owns the final state of these files):

- `AppModule.kt` — `boot()` installs `chatRoutes { di.direct.instance<ChatService>() }` (lazy; T12 keeps this wiring unchanged).
- `ServiceModule.kt` — `bind<ChatService>() with singleton { error("ChatService implementation lands in T12") }` (T12 replaces the placeholder).
- `build.gradle.kts` — `testImplementation("io.ktor:ktor-server-test-host-jvm:3.3.3")`.
