## Scaffold

Pinned-jar verification performed at scaffold time (D-16, Koog 1.3.0 sources + bytecode from the Gradle cache). The DeepSeek surface deviates from the D-16/task wording in three places, documented here for the correctness review:

1. **The DeepSeek client is NOT part of the pinned `ai.koog:koog-agents-jvm:1.3.0` distribution.** It ships as a separate artifact `ai.koog:prompt-executor-deepseek-client-jvm`, published only as `1.3.0-beta` (no stable 1.3.0 exists; 1.2.0-beta/1.1.1-beta are the older lines). `build.gradle.kts` gains an explicit `implementation("ai.koog:prompt-executor-deepseek-client-jvm:1.3.0-beta")` (integrator-owned, pre-staged at scaffold time; verified on the compile classpath). Its only compile dependency is `prompt-executor-openai-client-base-jvm:1.3.0` — already pinned transitively through koog-agents-jvm 1.3.0 — so the frozen 1.3.0 pin is not violated.
2. **`PromptExecutorBuilder` (pinned 1.3.0) has NO `.deepSeek(...)` method** (methods: `openAI`, `anthropic`, `ollama`, `fallback`, `addClient`, `build`). The verified wiring is `PromptExecutor.builder().addClient(DeepSeekLLMClient(...)).build()` → `MultiLLMPromptExecutor` dispatching by `model.provider == LLMProvider.DeepSeek`. (T13's scaffold note "`addClient(DeepSeekLLMClient(apiKey, baseUrl))`" is corrected by item 3.)
3. **D-16's constructor wording `DeepSeekLLMClient(apiKey, baseUrl = "https://api.deepseek.com")` is wrong in shape.** Verified constructors (Koog 1.3.0-beta sources):
   - `DeepSeekLLMClient(apiKey: String, settings: DeepSeekClientSettings = DeepSeekClientSettings(), httpClientFactory: KoogHttpClient.Factory, clock, toolsConverter)` — `httpClientFactory` is REQUIRED (no default) → the injectable MockEngine seam is preserved, exactly like T13.
   - There is no `baseUrl` parameter; the base URL lives in `DeepSeekClientSettings(baseUrl = "https://api.deepseek.com", chatCompletionsPath = "chat/completions", modelsPath = "models", timeoutConfig)` — all defaults match the DeepSeek API base, so no AppConfig base-URL key is needed (AppConfig stays untouched; `DEEPSEEK_API_KEY`/`DEEPSEEK_MODEL` already exist).

Verified surfaces used by the scaffold:
- **Auth**: `AbstractOpenAILLMClient.createConfiguredHttpClient` builds the client through `httpClientFactory.create(clientName = "DeepSeekLLMClient", baseUrl, headers = mapOf("Authorization" to "Bearer $apiKey"), ...)` → every outgoing request carries `Authorization: Bearer <DEEPSEEK_API_KEY>` (defaultRequest header in KtorKoogHttpClient) and `Content-Type: application/json`.
- **Wire**: `post(path = settings.chatCompletionsPath)` against the normalized base → request URL `https://api.deepseek.com/chat/completions` (MockEngine asserts: authority `https://api.deepseek.com`, encodedPath `/chat/completions`). Request/response are OpenAI-compatible: body `{model, messages, tools:[{"type":"function","function":{"name","description","parameters"}}], ...}` (OpenAICompatibleToolDescriptorSchemaGenerator — the same D-8 tool wire contract T13 asserted for local); response `{id, object:"chat.completion", created, model, system_fingerprint, choices:[{index, finish_reason, message:{role, content, tool_calls[]}}], usage?}` decoded with `Json { namingStrategy = SnakeCase; ignoreUnknownKeys = true; isLenient = true }`.
- **Test-recipe gotchas baked into the TODOs**: `system_fingerprint` is a NON-NULL `String` field of `DeepSeekChatCompletionResponse` — every MockEngine reply must include it (e.g. `""`) or decode throws; `message.tool_calls[].function.arguments` is a JSON STRING on the wire (`OpenAIFunction.arguments: String`); tool results return as role `"tool"` messages (assert identical to T13).
- **Model**: `LLModel(provider = LLMProvider.DeepSeek, id = config.deepseekModel)` — `LLMProvider.DeepSeek` verified in pinned prompt-llm 1.3.0.
- **Runner reuse**: `KoogChatRunner(promptExecutor, model)` / `runTurn(systemPrompt, history, userMessage, tools)` from T13 are consumed unchanged — no duplicated run logic. T14's tool-loop test passes a NON-EMPTY history (`user` + `assistant` entries) so the runner's history role-mapping path is finally exercised (T13's test gate noted it was uncovered).
