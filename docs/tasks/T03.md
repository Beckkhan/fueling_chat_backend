**Status:** `todo`

## Description
Add the tool descriptor file exactly as frozen in CONTRACT-TOOL-001, set up the `infra.db` module — one Exposed `Database` per production DB with HikariCP pools, server-side `readOnlyMode=always`, structure-only table objects — and the local Docker composition so the read paths are verifiable end to end; per spec §4, D-2 and design §6.

## Acceptance Criteria
- [ ] `resources/tools/get_fueling_info.json` is byte-identical to the JSON in CONTRACT-TOOL-001 (spec §3).
- [ ] Four Exposed `Database` bindings exist, named `fueling`, `gas_station`, `payment`, `vendors`, each with its own HikariCP pool, consuming DB URLs/credentials from `AppConfig` (design §2).
- [ ] `readOnlyMode=always` is set server-side on all four pools (spec §4).
- [ ] Exposed table objects are structure-only; `grep -r "SchemaUtils" src/main` shows no `SchemaUtils.create` call in main code (spec §4).
- [ ] Startup fail-fast covers DB reachability of all four DBs and a non-empty tool set, in addition to T02's config-completeness check: with a DB down or the tool JSON absent, the app crashes at boot with a clear message (D-2, design §6).
- [ ] `docker compose up -d` brings up `postgres:15-alpine` on port 25432 with the four databases; `docs/schema.sql` and `docs/seed.sql` apply cleanly against it (design §6, D-2).
- [ ] `./gradlew build` completes with 0 errors.
