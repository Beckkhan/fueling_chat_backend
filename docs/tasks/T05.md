# T05 - Database infrastructure

**Status:** `done`
**Owner:** `backend-coder`
**Dependencies:** `[T02]`
**Contracts:** `[CONTRACT-DB-001]`

## Description
Add the local Docker composition (one `postgres:15-alpine` on port 25432 with the four databases) and the `infra.db` layer — one Exposed `Database` per production DB on its own HikariCP pool, `readOnlyMode=always` server-side, structure-only table objects, and a startup reachability probe (design §6, D-2; spec §4).

## Acceptance Criteria
- [ ] `docker compose up -d` starts exactly one `postgres:15-alpine` container on port 25432 creating databases `fueling`, `gas_station`, `payment`, `vendors` via a mounted init script (design §6).
- [ ] `docs/schema.sql` and `docs/seed.sql` apply cleanly against the container (per-DB `psql`); the seed is idempotent — a second run succeeds with no new rows (spec §4, D-12).
- [ ] Four Exposed `Database` objects (`fueling`, `gas_station`, `payment`, `vendors`) each get their own HikariCP pool built from the `AppConfig` DB URLs/credentials (design §2); a test connects all four and asserts each database exposes its expected tables (13 tables total across the four DBs, spec §4).
- [ ] `readOnlyMode=always` is set server-side on all four pools (spec §4); a test attempting an `INSERT` through any pool is rejected by the server.
- [ ] Exposed table objects are structure-only: `grep -r "SchemaUtils.create" src/main` returns nothing (spec §4).
- [ ] Reachability probe: with one DB URL pointed at a closed port, the probe fails naming that database (unit test); the probe is wired into the boot order in T04 (design §6).
- [ ] `./gradlew build ktlintCheck detekt` completes with 0 errors.
