# T12 - ChatService & DialogHistory

**Status:** `in progress`
**Owner:** `backend-coder`
**Dependencies:** `[T11]`
**Contracts:** `[CONTRACT-SERVICE-001, CONTRACT-HISTORY-001]`

## Description
Implement the service layer of one chat turn on the `usual` branch, replacing the T11 placeholder: `ChatService` orchestrates the Koog run (system prompt per D-6/D-9, history, tool set per D-8, provider routing per D-10); `DialogHistory` is the write-through journal (D-1) with the in-memory cache as the only read source; `ProviderRouter` selects the named `LlmClient` binding (D-10).

## Acceptance Criteria
- [ ] `DialogHistory`: in-memory message list (`{role, body, timestamp}`) is the only read source; `.jsonl` journal (`DIALOG_HISTORY_FILE`, default `data/dialog-history.jsonl`, D-11) is written through per turn (user line + assistant line, kotlinx-serialization, append-only, `Mutex`-serialized); the journal is truncated at construction (startup) and the cache starts empty — restarts clear context (D-1); `recent(limit)` returns the last `HISTORY_LIMIT` (default 20, D-11) messages.
- [ ] `ChatService` assembles the tool set in the service layer — `listOf(getFuelingInfoTool)`, **never empty** — and passes it to `LlmClient.run(systemPrompt, history, userMessage, tools)` (D-8, pinned seam in spec §3). History passed = `DialogHistory.recent(historyLimit)`.
- [ ] System prompt built in the service: instruction to answer in the language of the user's latest message (D-6); fueling questions answered only via `get_fueling_info`; **D-9**: when `fueling_id` is present in the request the system prompt carries an explicit `attached fueling_id: <id> — use exactly this value for get_fueling_info` line (the LLM never extracts it from the text); when absent, no such line.
- [ ] `ProviderRouter`: `"local"` → the `local` named `LlmClient`, `"remote"` → `remote`, absent → `local` (D-10); any other value → `ChatFailure(400, masked)`; the router returns the provider name actually used (echoed in the response).
- [ ] After a successful run, both messages (user + assistant summary) are appended to `DialogHistory`; the service returns `ChatTurn(summary, provider)`; `elapsed_ms` remains the route's concern (T11).
- [ ] Failure classification (masked, per CONTRACT-SERVICE-001): DB failure (`ExposedSQLException`) → `ChatFailure(500, "Databases unavailable")`; provider unreachable (`LLMClientException`/`KoogHttpClientException`) or tool-loop break (`AIAgentException`) → `ChatFailure(502, "Provider unreachable")`; no raw SQL, credentials or provider text in messages or logs.
- [ ] `ServiceModule` binds `ChatService`, `ProviderRouter`, `DialogHistory`, replacing the T11 placeholder; `DiSmokeTest` additions land in T14 (both `LlmClient` bindings are still `error()` stubs until T13/T14, so resolving `ProviderRouter` through the app graph is deferred).
- [ ] Unit tests (MockK fake `LlmClient`, no network, no DB): D-9 injection present/absent asserted on the system prompt argument; history passed = last N with correct roles; journal file content after one turn = two JSONL lines matching cache; truncate-on-restart observable; provider routing incl. default and 400; 500/502 classification.
- [ ] `./gradlew build ktlintCheck detekt` completes with 0 errors.
