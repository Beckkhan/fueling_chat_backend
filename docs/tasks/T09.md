# T09 - API client & integration

**Status:** `todo`
**Owner:** `frontend-coder`
**Dependencies:** `[T08]`
**Contracts:** `[CONTRACT-API-001, CONTRACT-API-002]`

## Description
Add the typed `api/chat.ts` fetch client for `POST /chat` and wire the send flow, provider switching and the error bubble; one POST per message, no streaming or polling (D-7).

## Acceptance Criteria
- [ ] `api/chat.ts` POSTs `{prompt, provider}` (plus `fueling_id` when the user pinned one) as `application/json`; the `ChatRequest`/`ChatResponse` types in `types.ts` match CONTRACT-API-001/002 field-for-field (the 200 response has exactly `summary`, `provider`, `elapsed_ms`).
- [ ] The base URL comes from `VITE_API_URL` with default `http://localhost:8080` (D-13); the tracked frontend `.env.example` documents `VITE_API_URL=http://localhost:8080`.
- [ ] Send flow: optimistic user bubble → `POST /chat` → assistant bubble from `summary`; the `provider` field reflects the active model id (`local`/`remote`) — verified by tests with mocked `fetch` (design §5).
- [ ] Non-200 responses render the masked `{"error": …}` body in a muted error bubble; mocked tests cover the `400`, `500` and `502` shapes from CONTRACT-API-002's error table.
- [ ] Exactly one POST per send and no streaming/polling primitives: `grep -rE "EventSource|WebSocket|setInterval" src` returns nothing (D-7).
- [ ] `pnpm build`, `pnpm lint`, `pnpm test` all exit 0.
