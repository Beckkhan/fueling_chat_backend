# T02 - Typed AppConfig & fail-fast validation

**Status:** `todo`
**Owner:** `backend-coder`
**Dependencies:** `[T01]`
**Contracts:** `[CONTRACT-CONFIG-001]`

## Description
Implement the typed `AppConfig` that reads `.env` from the working directory and exposes every key of the tracked backend `.env.example` (design §2 config layer), failing fast on missing or empty required keys per the fail-fast guarantee of design §6.

## Acceptance Criteria
- [ ] `AppConfig` exposes one typed accessor per key of the tracked `.env.example`: `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, the four `*_DB_URL`s, `DEEPSEEK_API_KEY`, `DEEPSEEK_MODEL`, `OLLAMA_BASE_URL`, `OLLAMA_MODEL`, `KOOG_VERSION`, `DIALOG_HISTORY_FILE`, `HISTORY_LIMIT`; construction reads `.env` from the working directory.
- [ ] Keys documented with `<…>` placeholders in `.env.example` (`DB_PASSWORD`, `DEEPSEEK_API_KEY`, `DEEPSEEK_MODEL`, `OLLAMA_MODEL`) are required: loading an `.env` missing one of them or with it empty throws at construction with a message naming exactly that key — verified by a unit test per key.
- [ ] Keys documented with concrete values in `.env.example` fall back to those values when absent from `.env` (verified by a unit test with a minimal `.env` containing only the required keys).
- [ ] App crashes on startup if `DB_PASSWORD` is missing: the loader throws at construction and the entry point aborts with a non-zero exit before any other component starts (boot-order wiring lands in T04; the end-to-end crash is verified there).
- [ ] `./gradlew build ktlintCheck detekt` completes with 0 errors.
