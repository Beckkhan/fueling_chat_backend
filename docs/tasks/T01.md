# T01 - Backend scaffold & DI wiring

**Status:** `todo`
**Owner:** `backend-coder`
**Dependencies:** `[]`
**Contracts:** `[CONTRACT-DI-001]`

## Description
Create the Kotlin/Ktor backend project skeleton on the frozen stack (JDK 17+, Kotlin 2.x, Ktor netty, Kodein, Koog 1.3.0, Exposed + HikariCP, kotlinx-serialization, SLF4J + logback, JUnit 5 / MockK) and wire the Kodein composition per design §2: `AppModule` is the single DI entry point referenced from `Application`, which starts Netty and holds no business logic, SQL, or LLM calls.

## Acceptance Criteria
- [ ] `./gradlew build` completes with 0 errors on the scaffold (JDK 17+ toolchain).
- [ ] `Application.main` constructs the DI graph, starts Ktor on Netty, binds port 8080, and responds to HTTP (a request returns a Ktor response, not a connection refusal).
- [ ] `AppModule` composes the five modules from design §2 (`config`, `db`, `client`, `logging`, `service`) and the graph constructs without missing-binding errors; bindings themselves are populated by later tasks.
- [ ] `Application` references only `AppModule` and contains no business logic, SQL, or LLM calls (design §2).
- [ ] Build files pin the frozen stack: Kotlin 2.x, Ktor (netty), Kodein, Koog `ai.koog:koog-agents-jvm:1.3.0` (D-16), Exposed + HikariCP, kotlinx-serialization, SLF4J + logback, JUnit 5 / MockK (spec §8 backend README contract).
- [ ] Source layout follows the layer packages `config / infra.db / infra.llm / infra.logging / service / routes` (design §2).
