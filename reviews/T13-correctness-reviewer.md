## D-16 wording deviation verdict (explicitly required by the AC)

**The deviation is real, and the correction is right; the behavior matches the pinned jars.**

- The T13 task prose names "Ollama via its OpenAI-compatible endpoint" and implied an `OLLAMA_BASE_URL` default ending `/v1`. The pinned Koog 1.3.0 `OllamaClient` (`prompt-executor-ollama-client-jvm-1.3.0-sources.jar`) does **not** speak the OpenAI surface: `DEFAULT_BASE_URL = "http://localhost:11434"` and `DEFAULT_MESSAGE_PATH = "api/chat"`; requests are the native `OllamaChatRequestDTO(model, messages, tools, stream = false)` posted to `{base}/api/chat`, and there is no `/v1` or `chat/completions` code path in the module (the only "OpenAI" token is a model-card name). The `PromptExecutor.builder().ollama(...)` helper carries the same native default (`http://localhost:11434`).
- Consequently the architect's correction — base URL without `/v1`, `.env.example` updated, and the T02 `AppConfigTest` default assertion updated in the same commit — is the only configuration that works against the pinned client. Had `/v1` been kept, every turn would have posted to `{base}/v1/api/chat` → 404 → `LLMClientException` → masked 502.
- Note on the wording's home: spec D-16 itself already prescribes `OllamaClient(baseUrl = "http://localhost:11434")`, so the corrected default now matches D-16's normative text; the deviation was in the task prose only. One residual D-16 shorthand nuance (documentation-only): in 1.3.0 the literal call form `OllamaClient(baseUrl = …)` is not constructible — the class's public constructor takes `httpClientFactory` first (or one uses `PromptExecutor.builder().ollama(baseUrl, httpClientFactory)`), which is the form the implementation uses. No code consequence.

3. **Comment nit:** `ClientModule.kt:18` says Apache5 is "a transitive dependency of Koog's http-client-ktor"; `dependencyInsight` shows it arrives via `koog-agents-jvm:1.3.0`. The load-bearing claim (no new production dependency) is true.

Koog-side behavior, unreachable in the tested/realistic surface; noted for the trail only.
5. **Unknown history roles are silently dropped** by `KoogChatRunner.appendHistoryMessage`'s `else -> Unit` (gate 1 observation 2). `DialogHistory` only ever emits the two declared roles, so this is defensive code with no reachable production path.
6. **`AppConfigTest`'s remaining `/v1` strings (lines 82/101) are pass-through fixtures** — set and asserted identically — not a stale default; deliberately minimal diff, self-consistent.
7. **The production `HttpClient(Apache5)` is never closed.** It lives in an app-lifetime Kodein singleton with no shutdown hook; acceptable for this service and consistent with the app's lifecycle (Netty start/wait), noted only for completeness.
